Phase 0 gate is closed (guard proven RED then GREEN, sync_relay_state distinct, 16 latent payload gaps resolved). This task covers Phases 1 and 2 together — the UnitAvailability boundary in Phase 2 is what makes Phase 1b's output meaningful, so they land as one change set.

Phase 1 — Droop, and continuous loading as its dispatch-side expression

Governor droop is defined in the fixtures and never read in simulation_core.py, leaving the swing equation a pure integrator. Share-by-rating is the droop characteristic. These are one equation seen from two sides and land together.

1a. Wire droop into the swing equation

Read the configured droop constants. Governor response enters through frequency_forcing_mw explicitly — no implicit path, no second channel.

This phase changes numbers, not pixels. A droop-governed swing equation produces different frequency behaviour from a pure integrator on every existing scenario. Assertions in SC-01 through SC-12 may shift. That is a correction, not a regression — but the phase report must enumerate every changed assertion with the mechanism that changed it. Do not silently update expected values. If an assertion changes in a way you cannot explain mechanically, stop and report rather than adjusting it.

SC-12 work is not concurrent, so every scenario assertion change in this task is attributable to droop.

1b. Loading layer — pure function, evaluated every tick

Inputs: allocated set A, transitional set T (empty until Phase 3), fleet setpoint P_fleet (gt_setpoint_mw), current per-unit output. No stored state.

P_allocated = P_fleet − Σ_{i∈T} output_i
share_i     = rated_i / Σ_{j∈A} rated_j          # matched droop
              or rated_i/droop_i normalised       # mismatched droop, configured
raw_i       = share_i × P_allocated
setpoint_i  = clamp(raw_i, msl_i, rated_i)

Residual redistribution. If any unit clamps at msl_i or rated_i, redistribute the residual across unclamped units by share and re-clamp. Bounded set, monotone residual, terminates within |A| passes. Must be order-independent — assert it.

Movement toward setpoint, all units, both directions:

output_i ← output_i + clamp(setpoint_i − output_i, −r_i·Δt, +r_i·Δt)

Ramp capability over horizon H:

ramp_capability(H) = Σ_{i∈A} min(r_i × H, rated_i − output_i)

Units in STARTING contribute zero for any H < time_to_online_i, and their rated contribution beyond it. That is the entire cold-unit rule — no special case, no caption.

Delete the Phase 0.5 display cap. The cap at installed MW in turbineFleet.ts was a display-level stopgap and is not the specified clamp. ramp_capability(H) is the sole path; the drawer reads it as a typed field. Two clamps means two values and the wrong one on screen.

Feasible band. n allocated units produce only within [Σ msl, Σ rated]. When P_allocated falls below Σ msl, hold at the floor and populate sub_msl_surplus_mw for the drawer. Do not decommit. Do not route it into BESS charging. Do not resolve it in any way. The resolution of that case is deferred pending operator feedback.

Phase 1 acceptance

Loading layer holds no state between calls. Grep the diff: no instance attributes, no module globals, no memoisation, no cached shares.
Identical (A, T, P_fleet, outputs) yields identical setpoints across calls, process restarts, and permutations of unit ordering.
The Phase 0.5 display cap is deleted; ramp_capability(H) is the sole ramp path and reaches the drawer as a typed field.
Every scenario assertion changed by 1a is enumerated with its mechanism.
Phase 2 — Unit states and the availability boundary

Five states. Output is a float, not a state.

State	output_mw	In A?	Carries
OUT_OF_SERVICE	0	No	out_of_service_reason, declared-at timestamp
OFFLINE	0	No	min_down_time_remaining_s, thermal_state
STARTING	0	No	time_to_online_s, start_phase
TRANSITIONAL	continuous	No — in T	direction, target_mw
SYNCHRONISED	continuous	Yes	output_mw

TRANSITIONAL is defined now and unreachable until Phase 3. Define the state and its payload fields; do not implement the sequences that enter it.

start_phase (purge / accelerate / synchronise) is a display and fault-injection label. No arithmetic branches on it.

out_of_service_reason is one of operator | fault | maintenance. This is the meaning of "override": a unit declared out by an operator must never be returned to service by any automatic logic. Record it now — cheap here, awkward to retrofit when commitment logic arrives.

Thermal state (COLD / WARM / HOT) determines start duration, transitioning on time since last synchronisation. All thresholds from config, no literals.

Constants for this build — engineering placeholders pending OEM data, registered alongside r_asset under §15. Configuration fields, not literals in code.

Constant	Value
min_down_time_s	600 (10 min)
unload_tail_s	60

Minimum run time is not enforced by GridSignal. It is an OEM machine-protection constraint belonging to the turbine controller. GridSignal displays the timer; the plant owns the rejection.

Availability crosses a boundary as an observation — the interface a PMS would populate at a real site:

UnitAvailability:
  unit_id, state, output_mw, rated_mw, msl_mw,
  r_asset_effective_mw_per_s,   # re-rated if applicable, TC-58
  time_to_online_s,             # 0 when SYNCHRONISED, null when OUT_OF_SERVICE
  out_of_service_reason         # null unless OUT_OF_SERVICE

Migrate the existing reserve check and N−1 tile to read from this rather than the turbine model directly. Their logic is unchanged in this scope — input path only. Build this boundary even though no new consumer needs it yet; it is the seam that lets commitment logic attach later without touching the turbine model. This is the one place in this task where building ahead of need is intended.

Report P_anchor_reserve at the San Diego site, whether or not it is zero. TC-63 requires it never default to zero. Nothing here depends on its value, but a pre-existing zero must not be mistaken for a defect introduced by the input-path migration. Do not change it as part of this work.
