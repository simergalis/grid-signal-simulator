Context

The simulator currently emits step_event using a tick-counter modulo (tick % 7 == 0). This produces a period of exactly 0.700 s with zero jitter: across a 60 s / 10 Hz capture, all 85 events landed on sample indices that were exact multiples of 7, and every inter-event gap was exactly 7 samples — never 6, never 8.

Two problems follow from this:

The period is defined in ticks, not seconds. Changing the sample rate would silently change the physical step time.
compute_load_mw does not respond to step_event at all. Spectral power in the load at the step frequency (1.429 Hz) measures 0.04%, against a white-noise baseline of 0.33% — an order of magnitude below noise. The event channel is currently decorative.

This phase fixes both: replace the counter with a seeded stochastic process in continuous sim time, and wire it into the compute load model so the pulse is physically present.

Hard constraint: use numpy/stdlib pseudorandom number generators only. Do not call any LLM, external API, or network service to produce randomness or step timings. All stochasticity must be local, seeded, and reproducible.

Part 1 — Replace the tick counter with a continuous-time step process

Delete all tick % N logic for step generation. Replace with a scheduler holding next_step_time in seconds of sim time, independent of tick rate.

1.1 Base step duration — lognormal

Step time in synchronous distributed training is gated by the slowest worker, so it is a maximum over N workers: right-skewed with a tail. Model it as lognormal.

Given configured median_step_s and step_cv:

sigma = sqrt(ln(1 + step_cv**2))
mu    = ln(median_step_s)
D     = exp(rng.normal(mu, sigma))

Defaults: median_step_s = 0.70, step_cv = 0.08.

1.2 Slow drift — Ornstein-Uhlenbeck on the log-median

Real clusters drift as thermal state and network contention evolve. Apply an OU process to mu:

mu_t = mu_0 + x_t
dx   = -(x_t / tau_drift) * dt + sigma_drift * sqrt(2*dt/tau_drift) * rng.normal()

Defaults: tau_drift_s = 300.0, sigma_drift = 0.03 (≈3% drift in median step time).

1.3 Straggler outliers

With probability p_straggler per step, multiply the drawn duration:

D *= 1.0 + rng.exponential(straggler_scale)

Clamp the total multiplier at straggler_max to avoid absurd tails. Defaults: p_straggler = 0.02, straggler_scale = 1.5, straggler_max = 10.0.

1.4 Checkpoint and eval boundaries

Every ckpt_interval_steps steps (± uniform jitter of ckpt_jitter_steps), inject a long step drawn from uniform(ckpt_min_s, ckpt_max_s) and set a step_kind field to "checkpoint".

Defaults: ckpt_interval_steps = 400, ckpt_jitter_steps = 40, ckpt_min_s = 5.0, ckpt_max_s = 30.0.

This should drive the existing checkpoint-valley classifier rather than duplicating it — emit the event and let the classifier detect it.

1.5 Emission

On each tick, if sim_time >= next_step_time, emit the event and schedule next_step_time += D. Because D is continuous and the tick grid is discrete, observed gaps will naturally vary between 6, 7, and 8 samples at 10 Hz. Do not round D to the tick grid. Carry fractional remainder forward so long-run mean step time is preserved exactly.

Add a step_phase column in [0, 1) giving position within the current step — needed for Part 2 and useful for debugging.

Part 2 — Couple the step process to compute_load_mw

This is the part that makes the pulse real. Currently compute_load_mw is a linear rescale of compute_cpu_load_pct (correlation +0.9994) with no step structure.

2.1 Within-step power profile

Each step has a compute phase (GPUs near TDP) and a communication phase (all-reduce; GPUs largely idle waiting on the network):

Fraction f_compute of the step at relative power 1.0
Remaining 1 - f_compute at relative power p_comm_ratio

Defaults: f_compute = 0.72, p_comm_ratio = 0.55.

2.2 Transition smoothing

GPU power does not square-wave. Apply a first-order lag with time constant tau_gpu_s = 0.06 to the phase profile so edges have finite slope.

2.3 Phase coherence across the fleet

A single GPU idling during all-reduce is noise; ten thousand idling during the same all-reduce is a coherent multi-megawatt square wave. Model this with phase_coherence in [0, 1]:

effective_profile = 1.0 + phase_coherence * (raw_profile - 1.0)

Default phase_coherence = 0.85. Setting it to 0.0 must collapse the pulse entirely — that is a required test case.

2.4 Assembly
compute_load_mw = job_base_draw_mw * effective_profile + idle_baseline_mw + noise

Keep the existing measurement noise term. compute_cpu_load_pct should be derived from compute_load_mw, not the other way round, so it inherits the pulse.

Part 3 — Seeding and stream isolation
3.1 No global RNG

Do not use random.seed(), np.random.seed(), or any module-level RNG. Every stochastic component receives an injected numpy.random.Generator.

3.2 Independent child streams

Use SeedSequence.spawn() to give each subsystem its own stream:

python
ss = np.random.SeedSequence(scenario.rng_seed)
children = ss.spawn(8)
rng_step, rng_load, rng_thermal, rng_solar, rng_bess, rng_cooling, rng_meas, rng_reserve = \
    (np.random.Generator(np.random.PCG64(c)) for c in children)

This matters: with a single shared stream, adding one draw to the cooling model shifts every subsequent draw in every other subsystem, and scenario replays stop being comparable across code changes. Isolated streams keep runs diffable.

3.3 Seed provenance
If scenario.rng_seed is unset, generate one from entropy and write it back to the scenario record.
Emit rng_seed, schema_version, and scenario_id into the CSV metadata header (or a sidecar JSON if the CSV format is fixed).
A run must be exactly reproducible from its seed.
Part 4 — Configuration surface

Expose every parameter above in a dataclass or YAML block with the stated defaults. No magic numbers in the simulation loop. Group as step_timing, load_profile, rng.

Part 5 — Acceptance criteria

All tests run against a 600 s capture at 10 Hz unless stated otherwise. Add these to the pytest suite.

Timing distribution
#	Criterion	Threshold
T1	Distinct inter-event gap values (in samples)	≥ 3
T2	Standard deviation of gap	≥ 0.30 ticks
T3	len(set(event_index % 7))	> 1
T4	Measured CV of step duration vs configured	within ±15%
T5	Sample skewness of step durations	≥ 0.5
T6	Mean step duration vs median_step_s * exp(sigma²/2)	within ±3%
Tick-rate independence
#	Criterion	Threshold
T7	Mean step duration at 20 Hz vs at 10 Hz, same seed	within ±2%

T7 is the critical one — it is what proves the period is defined in seconds rather than ticks. The current implementation fails it by construction.

Spectral signature
#	Criterion	Threshold
S1	Peak-bin power share of event train at nominal step frequency	≤ 5% (currently 20.0%)
S2	Power in ±15% band around nominal frequency	≥ 15%
S3	Power in compute_load_mw in that ±15% band	≥ 10× the white-noise baseline of 100/n_bins %

S3 is the coupling test. Current value is 0.04% against a 0.33% baseline — a factor of 8 below noise. It must end up well above.

Load pulse
#	Criterion	Threshold
L1	Peak-to-peak of compute_load_mw as % of mean	≥ 20%
L2	Same, with phase_coherence = 0.0	≤ 3%
L3	Phase-folded fold amplitude ÷ residual sd (SNR)	≥ 3.0 (currently 0.049)
Determinism
#	Criterion	Threshold
D1	Two runs, identical seed	byte-identical CSV
D2	Two runs, different seeds	differ, but KS test on step durations gives p > 0.01
D3	Adding a draw to any one subsystem	does not alter any other subsystem's output

D3 is what stream isolation buys; assert it explicitly.

Part 6 — Optional follow-on (do NOT include in this change set)

Flagging for sequencing only. compute_inlet_temp_c is currently an independent uniform draw per sample — lag-1 autocorrelation measures +0.094 at 10 Hz, where a real thermal mass would exceed 0.99. Replacing it with an OU or first-order-lag process driven by IT load is a separate phase, since it belongs with the dual-clock thermal lag work rather than here.

Out of scope for this phase
Do not modify the generation-side plant model (turbine, solar, BESS).
Do not alter the balance equation or the grid_import_mw slack behaviour.
Do not change the dispatch arbitration logic.
Do not introduce any LLM, external API, or network dependency.
Deliverables
Modified step scheduler with the continuous-time stochastic process.
Modified compute load model with within-step power profile.
RNG stream isolation via SeedSequence.spawn().
Config dataclass/YAML with all parameters.
pytest suite covering T1–T7, S1–S3, L1–L3, D1–D3.
A 600 s / 10 Hz sample capture committed as a fixture for regression comparison.
