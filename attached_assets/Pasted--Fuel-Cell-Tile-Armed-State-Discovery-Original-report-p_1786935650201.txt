# Fuel Cell Tile "Armed" State — Discovery

Original report (predates IMPL-FC-HEADROOM-001, unrelated code path): the Fuel Cell Module
Array tile on the plant diagram shows "armed" as a pre-run standby cosmetic state regardless
of whether the current scenario actually has a fuel cell configured. This has not yet been
confirmed as a real bug or ruled out — the IMPL-FC-HEADROOM-001 investigation touched
`kube_demand.py` and `simulation_core.py`'s admission-headroom path, which has no code
relationship to frontend tile rendering. Do not assume that fix covers this.

This is discovery only. Read-only, no files created or modified. Do not propose or make a fix.

1. **Locate the tile component.** Find the frontend component rendering the Fuel Cell Module
   Array tile (plant diagram, "armed / standby" style state label — likely a `FuelCellTile`
   or similarly named `.tsx` file). Report the file path.

2. **Trace the state source.** What prop, store value, or hook does the tile read to determine
   its displayed state ("armed" vs. any other value)? Is it:
   - A literal hardcoded string with no conditional logic, or
   - Derived from some scenario/asset field — and if so, which field, and does it match
     `fuel_cell_rated_mw` / `fuel_cell_enabled` (the fields confirmed in
     IMPL-FC-HEADROOM-001 Phase 1 as the source of truth in `scenario_factory.py`), or a
     different/stale field?

3. **Test both cases directly.** Load or point to two scenarios — one with
   `fuel_cell_enabled: true` and one without (`kube_config: null`/no FC scenarios qualify).
   Report what the tile actually renders in each case, from the live app or component test,
   not from reading code alone. Screenshot or copy the rendered text if possible.

4. **Determine disposition.** Based on 1–3, classify this as one of:
   - **Confirmed bug** — tile ignores scenario config and always shows "armed" regardless.
   - **Not a bug, mislabeled** — tile does react to config, but "armed" is simply the correct
     idle/standby label when a fuel cell is present but not dispatching (distinguish this from
     the no-FC-configured case, which should presumably show something else entirely, like
     "not installed" or the tile omitted).
   - **Not a bug, no fuel cell absence case exists yet** — the tile has no state for "fuel cell
     not configured" at all, meaning it can't help but show something misleading when FC is
     absent; this would be a real gap but a different one than the original report implied.

**Report all four items. Do not write a fix regardless of which disposition you find.**
