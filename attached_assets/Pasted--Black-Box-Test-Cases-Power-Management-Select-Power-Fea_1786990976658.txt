**⚠ SPEC GAP — SPEC-GAP-PWR-001 (open item, do not guess):**  
The formal acceptance matrix (TC-01–TC-76) and Build Plan v2.2 contain **no named TC or specification section** explicitly governing:
- The "Select Power" / `PowerSupplySourcesModal` source-toggle UI
- The per-tile aggregate-inclusion toggle (`PlantNode` indicator)
- The "⊙ Select Power · X.XX MW" footer aggregate display
- Tile and flow-line visibility behavior when sources are deselected via the modal

The feature is implemented and observable, but no spec document (GS-DES-GRID-001 or the Forecast Engine Functional Spec v2.5) has been located that defines the required behaviour for these controls. Test cases in Categories A and B therefore assert **observed implementation behaviour** as the baseline, not a spec-derived invariant. Any test that would fail should be treated as a signal to either (a) file a spec defect or (b) file an implementation defect — the triage belongs to the spec owner.

Categories C and D cite GS-IMPL-PSP-002 §6.1 / TC-68 where the advisory boundary is the governing invariant.

## Architecture Summary (required for accurate test framing)

Two distinct sub-systems share the "Select Power" label. Tests must not conflate them.

### Sub-system 1 — Scenario Spec Source Selection (`PowerSupplySourcesModal`)
- Opened by clicking the **"⊙ Select Power"** footer button in the plant diagram.
- Shows pill toggles for five sources: BESS, Gas Turbine Fleet, Solar PV, Fuel Cell Module Array, Grid Connection.
- **SAVE → PUT `/scenarios/{id}`** writes a full spec replacement. Fields modified:
  - `turbine_units: []` (disabled) or restored array (enabled)
  - `bess_units: []` (disabled) or restored array (enabled)
  - `solar_rated_mw: 0` (disabled) or restored positive value (enabled)
  - `fuel_cell_enabled: boolean`
  - `island_mode: !gridSelected`
- On success the scenario store (`scenarioStore`) is updated in-memory immediately.
- The physics engine reads these same fields at run-start to decide which asset modules to instantiate. Unselected sources receive no SCADA commands because the modules are never constructed.
- **CANCEL** discards all changes; no API call is made.

### Sub-system 2 — Per-Tile Aggregate Toggle (`PlantDiagram` / `PlantNode`)
- A small filled/hollow circle indicator in each **enabled** source tile header.
- Click → includes or excludes that tile from the running MW total in the "Select Power" footer.
- **Display-only: no API call, no spec write, no persistence.**
- State lives in React (`Set<string> includedInAggregate`) and is lost on page refresh.
- Auto-sync rule: when a source is disabled via the modal, it is removed from the set; when a source is newly enabled, it is auto-added to the set.
- Solar MW prefers the 1.5 Hz polled value (`liveSolarMW`) over the WebSocket tick field.
- BESS: only positive output (discharge) contributes to the aggregate; charging is excluded.

### Advisory boundary (inviolable — GS-IMPL-PSP-002 §6.1)
GridSignal never issues southbound writes (Modbus, DNP3, OPC UA, IEC 61850).
SCADA layer permits only `TURBINE_SETPOINT` and `BESS_DISPATCH` command types (TC-68).
PMSTestDouble applies an operator response profile to advisory outputs and logs actions;
it does not command physical switchgear.
"Enable/disable a power supply module" in GridSignal means writing the scenario spec
(configuration-time), not issuing a real-time enable command to the PMS.

## Category C — Signal Behavior to Switchgear / PMS (~16 tests, incl. BB-PWR-051)

> **Frame for this category:** GridSignal's architecture (GS-IMPL-PSP-002 §6.1) prohibits all
> southbound writes. "Selectively receive signals from SWITCHGEAR/PMS" means the physics
> engine is configured, at run-start, to instantiate only the asset modules corresponding to
> the spec-enabled sources. The SCADA layer (`scada_layer.py`) then issues `TURBINE_SETPOINT`
> and `BESS_DISPATCH` commands for those modules only. No enable/disable command is ever sent
> to a physical PMS or switchgear unit; GridSignal advises, never commands.
