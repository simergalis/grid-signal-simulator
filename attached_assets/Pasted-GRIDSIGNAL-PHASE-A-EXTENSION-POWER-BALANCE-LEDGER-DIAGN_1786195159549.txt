GRIDSIGNAL — PHASE A EXTENSION: POWER BALANCE LEDGER
DIAGNOSTIC ONLY. NO BEHAVIOURAL CHANGES.

CONTEXT
A dashboard snapshot of the islanded 8-60-10 scenario shows sources
(GT 30.00 + solar 1.25 + BESS discharge 17.00 = 48.25 MW) against sinks
(compute 63.04 + cooling 12.76 = 75.80 MW), a residual of -27.55 MW.
Power balance in an island is an identity. A residual of this magnitude
is a defect. We do not yet know whether the defect is in the physics, in
the dispatch, or only in what the tiles are reading. This work determines
which. It does not fix anything.

1.  Do NOT modify gridsignal_scenario_islanded_8_60_10.json.
2.  Do NOT modify gridsignal_parameters.json.
3.  Do NOT change any physics, dispatch, commitment, cooling, solar,
    BESS, or frequency logic.
4.  Do NOT change any display, formatting, or UI logic.
5.  Do NOT add clamps, guards, corrections, fallbacks, or defaults.
6.  Do NOT tune, adjust, or "align" any parameter for any reason.
7.  Do NOT recompute any logged quantity. Read the value the existing
    code already computed, at the point it is consumed. A second
    implementation of an existing quantity is a dual implementation and
    is prohibited.
8.  Do NOT rename, remove, or restructure existing fields.
9.  Do NOT introduce any RNG.
10. Do NOT edit any specification document, decision record, or test

11. Do NOT fix any defect you discover. Log it and report it.

Produce a table mapping each of the six Site Overview tiles to the actual
data path behind it:

  tile -> frontend prop -> API response field -> backend source expression
       -> the function/line where that value is produced

Tiles: Gas Turbine Fleet, Solar PV, Battery (BESS), Compute Racks,
Cooling Plant, Grid Connection.

For each tile also report every secondary field it renders, with the same
mapping. Specifically required, because their meaning is currently
unknown:
  - Gas Turbine Fleet: "units", "online", "N-1 firm"
  - Solar PV: "exp" (state what this field actually is — expected output,

  - Battery: "discharging" flag, MW figure sign convention, SoC
  - Cooling Plant: "rated" and "headroom" (report the exact expression

  - Compute Racks: job count and MW

State, for each MW figure, whether it is (a) a modelled/demand quantity,
(b) a commanded setpoint, or (c) a delivered/served quantity — and cite
the producing expression as evidence. Do not answer from the field name.

Also report the simulation tick period actually in use and where it is
read from.

ACCEPTANCE: table complete, every row citing a file and line. No code
modified — `git diff` is empty.
STOP AND REPORT. Do not proceed to A-2.

PHASE A-2 — PER-TICK BALANCE LEDGER
Emit one JSONL record per simulation tick to
  runs/<run_id>/phaseA_balance_ledger.jsonl

Each record contains, all in MW unless noted:
  t_s
  turbines: [ {unit_id, state, p_mw} ]   (per unit, not aggregate)
  p_turbine_total_mw
  p_solar_mw
  p_bess_mw                 (signed; state the convention in the header
                             record, do not assume one)
  p_source_total_mw
  p_compute_modeled_mw
  p_compute_served_mw
  p_cooling_modeled_mw
  p_cooling_served_mw
  p_curtailed_mw
  p_unserved_mw
  p_sink_total_mw
  residual_mw               (sources - sinks)
  frequency_hz
  soc_frac
  floor_violated
  dispatch_state

For any field above that has no existing producer in the code, emit the
literal string "ABSENT" for that field and list it in your report. Do NOT
create a producer for it. "ABSENT" is a finding, not a gap to fill.

Write one header record at t=0 declaring, for each field, the source
expression it was read from and the sign convention where applicable.

ADD ONE ASSERTION, non-fatal: when |residual_mw| > 0.01, append a record
to runs/<run_id>/phaseA_defects.jsonl with the tick, the residual, and
all terms. Do not halt the run. Do not alter any state.

ACCEPTANCE:
 - Ledger written for every tick of the run.
 - Header record present and complete.
 - AT-7 determinism holds: simulation output is bit-identical to a
   pre-instrumentation run from the same seed. If it is not, the
   instrumentation has perturbed state — revert and report, do not
   attempt to compensate.
STOP AND REPORT. Do not proceed to A-3.

PHASE A-4 — RUN AND REPORT
Run the islanded 8-60-10 scenario unchanged, from the existing seed.
Report:
 1. Suite delta: tests passing/failing before vs after. Any delta at all
    is a failure of this work and must be reported, not fixed.
 2. AT-7 result: bit-identical or not.
 3. First tick at which |residual_mw| > 0.01, and the residual at the
    tick corresponding to the snapshot (compute ~63.04 MW, 2 turbines
    online).
 4. Residual time series summary: max, min, and whether it is monotone
    with the compute ramp.
 5. Whether p_compute_served / p_cooling_served exist at all, and if so
    whether they differ from the modelled values.
 6. Whether any insufficient-reserve alert was raised at any tick, and
    at what tick.
 7. Number of ticks with commit_request_issued = true; value of
    urgency_term_U across the run; whether any unit was ever in a
    starting state.
 8. Every field that emitted "ABSENT".
 9. Every defect observed, listed, unfixed.

Do not draw conclusions about root cause. Report values.
