# GridSignal Simulator — Fabric Model

Implements Simulator Functional Specification Section 12. Replaces the eight
unpopulated fields in the Network Fabric modal with derived, deterministic,
mutually consistent values.

## Layout

```
fabric/
  prng.py         counter-based PRNG, tuple-addressed (12.7)
  topology.py     fixture loading, link construction (12.2)
  traffic.py      job phase -> flow generation (12.3)
  stressors.py    injectable stressor library (12.8)
  model.py        routing, derived metrics, control path, corroboration (12.4-12.6, 12.9)
  instrument.py   session transport, measured never simulated (12.10)
  scenario.py     scenario loading, metric extraction, assertion evaluation
config/
  fabric_fixture_default.json           topology
  fabric_constants.json                 thresholds, tiers, emission
  workload_traffic_profiles.json        phase -> traffic map
  workload_traffic_profiles_slow_checkpoint.json
  scenarios/S1..S8                      eight scenarios with assertions
  schema/                               JSON schemas
tests/test_fabric_model.py              TC-77 .. TC-85
mockups/render_mockups.py               renders the reference screenshots
```

## The three things this model gets right

**Derivation, not generation.** Headroom, congestion, loss and retransmit all
fall out of one utilisation figure. Independently generated fields are
individually plausible and mutually contradictory, and the contradiction is
found by the first engineer who does arithmetic on the screen.

**Spraying works for many-small and fails for few-large.** Compute-fabric
allreduce traffic is sprayed and loads uplinks evenly. Storage elephants are
pinned by ECMP hash — a balls-in-bins draw. So hotspots appear during
checkpoint and not during steady training, which is the production pathology
and the reason elephant-flow detection appears in Engine 25.3 at all.

**Direction separates checkpoint from job start.** A checkpoint is a large
storage WRITE. Weight load at job start is an equally large READ. A rate-only
signature corroborates a checkpoint at the exact moment a job begins. See
TC-82b.

## What is deliberately absent

No language model anywhere in this path. Arithmetic over a seeded PRNG only,
for the same reason Engine 21.1 excludes inference from the control plane: a
non-reproducible input makes the scenario assertions untestable.

The intra-rack scale-up domain is not modelled. Collectives inside an
NVLink-class domain never traverse a switched fabric and are invisible to
NetworkTelemetry. Modelling them would manufacture a signal the real product
cannot observe.

## Unvalidated constants

Every threshold here is chosen for shape, not fitted to a site. See
Simulator Spec FM-1 through FM-5 and Engine Spec NT-5. A demonstration built on
this shows that the discrimination works, not how well it works at any
particular site, and should be described that way to an audience.
