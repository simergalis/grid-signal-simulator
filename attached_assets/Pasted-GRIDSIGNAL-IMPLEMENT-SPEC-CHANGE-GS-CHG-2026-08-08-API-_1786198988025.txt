WHAT THIS TASK IS
v2.7 splits the former P_total symbol into P_demand, P_served,
P_unserved, and P_imbalance, and adds P_generation. It states the power
balance identity as an invariant (3.2) and adds a second governing rule
to Section 19: a console surface renders values, it does not compute
them.

This task implements the CONTRACT and the DISPLAY for those symbols, and
lands the Section 16.14 acceptance tests. It does NOT implement the
balance solver. The frequency dynamics specification does not yet exist,
and implementing physics against an absent specification is prohibited.

EXPECTED OUTCOME — READ THIS TWICE
P_served, P_unserved, and P_imbalance HAVE NO PRODUCER TODAY. That is
expected and correct.

At the end of this task:
  - the API returns those fields as null
  - the tiles render them as explicitly unavailable
  - TC-87 through TC-91 FAIL
  - TC-92 PASSES

A run in which TC-87 through TC-91 pass is a FAILURE OF THIS TASK. It
means producers were invented. Per Spec 3.2, P_served is an output of the
electrical solution; anything else assigned to it is one of the three
defective implementations that section names.

DO NOT create producers for P_served, P_unserved, P_imbalance, or
P_generation. DO NOT derive them. DO NOT default them to zero, to
P_demand, or to any placeholder that reads as a measurement. A displayed
zero not produced by the simulation is a false statement about site
physics (Spec 19).
