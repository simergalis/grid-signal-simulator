## Phase 3 — Transitional loading

**The problem this solves.** Dropping a unit out of the allocated set instantly enlarges every remaining unit's share; they all ramp up while the departing unit ramps down. Adding a unit does the inverse and the fleet lurches downward. Both produce a transient nobody commanded.

**The mechanism, one for both directions.** A unit entering or leaving service is `TRANSITIONAL`: it follows its own commanded trajectory at its own ramp limit. Allocated units share the remainder, `P_fleet − Σ_{i∈T} output_i`, which grows as a departing unit sheds and shrinks as a joining unit loads — matched tick for tick. Fleet total is preserved throughout.

`TRANSITIONAL` and its payload fields were defined in Phase 2 and are currently unreachable. This phase implements the sequences that enter and leave it.

**Constants** — engineering placeholders under §15, configuration fields, not literals:

| Constant | Value |
|---|---|
| `min_down_time_s` | 600 (10 min) |
| `unload_tail_s` | 60 |

### Out-of-service sequence (`direction: decreasing`)

1. `SYNCHRONISED` → `TRANSITIONAL`, `target_mw = msl_mw`.
2. Output ramps down at `r_i`. The allocated set absorbs the shed as its remainder grows.
3. At `msl_mw`, breaker opens → `OFFLINE`, ramping to zero over `unload_tail_s`.
4. `min_down_time_s` timer starts → `OUT_OF_SERVICE`, `out_of_service_reason: operator`.

### Into-service sequence (`direction: increasing`)

1. `OUT_OF_SERVICE` → `OFFLINE` on return-to-service, subject to `min_down_time_s` having elapsed.
2. → `STARTING`. `time_to_online_s` counts down through `start_phase`. Output stays zero. **Contributes zero ramp credit at any horizon** (per #198 item 2).
3. Breaker closes at `no_load_mw` → `TRANSITIONAL`, `target_mw` = its proportional share of `P_fleet`.
4. Output ramps up at `r_i`. Allocated units give way as the remainder shrinks.
5. On reaching its share → `SYNCHRONISED`, joins `A`.

**Graduation from `T` to `A` is on reaching share, not on a timer.** The loading layer stays pure: transitional membership is unit state read as input, never state held inside the function.

**Interaction with the mutual-exclusion guard.** A `TRANSITIONAL` unit must not be eligible for `advance()`. Extend `_check_loading_exclusion()` to cover the transitional set, and prove the extension fires.

**Phase 3 acceptance**
- Fleet total output over a full out-of-service sequence deviates from `P_fleet` by no more than one tick's aggregate ramp at any tick. No step, no lurch.
- Same assertion over a full into-service sequence from `COLD`.
- No unit's output changes by more than `r_i · Δt` in any tick, in any state, in either direction.
- An into-service sequence from `COLD` produces zero output for the full configured start duration, and zero ramp credit throughout `STARTING`.
- The loading layer still holds no state between calls. Re-verify after the transitional changes: no instance attributes, no module globals, no memoisation, no cached shares.
- `_check_loading_exclusion()` covers `TRANSITIONAL` and is proven able to fail.

**Stop and report before Phase 4.**

## Phase 4 — Operator override surface

Two actions. Both gradual, both durable, neither instant.

**Endpoints** (simulator control plane, existing FastAPI app):
- `POST /api/plant/turbine/{unit_id}/out-of-service` — body: `reason`, operator identity
- `POST /api/plant/turbine/{unit_id}/into-service` — body: operator identity

**Rules**

- Every command validates against the state machine and returns a **structured rejection naming the violated constraint and any seconds remaining**. Never a silent no-op, never a queued retry.
- Every accepted command produces a `ControlEvent` tagged `source: plant_control` with operator identity. GridSignal-originated events carry `source: gridsignal` and are a disjoint set.
- The breaker close at the end of `STARTING` is performed by the simulated synchro-check relay. **No code path from GridSignal to that close may exist.**
- **`out_of_service_reason: operator` is durable.** A unit declared out by an operator is returned to service only by an explicit into-service command. No automatic path may return it — this is the meaning of "override," and it must hold before commitment logic exists to violate it.
- **If a command breaks N−1 or fails the reserve check, pre-flight the consequence in the confirmation and let the operator proceed anyway.** Blocking would give GridSignal veto authority over plant operation, contradicting §7.2 advisory tiering. The operator may know something the forecast does not — a bearing temperature, a vibration trend, a person inside the enclosure.
- **Minimum run time is not enforced by GridSignal.** It is an OEM machine-protection constraint belonging to the turbine controller. GridSignal displays the timer; the plant owns the rejection.

**UI**

- Per-unit action in the drawer, two-step confirmation showing: current state, any timer remaining, estimated sequence duration, and the resulting N−1 verdict if executed.
- Live progress for any unit in `TRANSITIONAL` or `STARTING`: current output, target, seconds remaining. An operator watching a cold unit take eight minutes to return is the most honest moment in the demo — show the clock.
- All displayed scalars come from typed `TickPayload` fields. The Phase 0 broadcast-key guard applies to every field added here.

**Phase 4 acceptance**
- **TC-68 unchanged.** Full run with the override exercised, commands captured at the GridSignal egress boundary: zero islanding, synchro-check, anti-islanding, droop, or protective-shed commands from GridSignal, and zero per-unit MW setpoints.
- Taking the last synchronised unit out of service is permitted, pre-flighting the resulting verdict in the confirmation.
- A rejected command returns a named constraint plus seconds remaining, and changes no state — fleet state bit-identical before and after.
- No automatic code path returns an `operator`-declared unit to service.
- Broadcast-key guard green with all new fields.
