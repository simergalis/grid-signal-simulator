D1 — Turbine Output Single-Writer Fix

Target model: core/simulation_core.py, core/loading.py, core/asset_modules.py (live engine). NOT gridsignal_logger.py. If any instruction below appears to apply to the logger, stop and report.

Scope: one defect. Do not fix anything else found along the way — record it and report at the end.

The defect

Phase 1 diagnostics (D1) established that two writers touch _current_output_mw on the same turbine within a single tick:

apply_loading() → t.set_output(setpoint) — simulation_core.py:650-652 → asset_modules.py:821. Operates on every unit where is_synchronised == True, which per asset_modules.py:810-814 includes RAMPING and AT_TARGET.
TurbineModule.advance() — asset_modules.py:990-999, reached via arbitrator.tick() at simulation_core.py:659. Adds r_asset × dt to _current_output_mw on RAMPING units.

Because (2) runs after (1), a RAMPING turbine's output for the tick resolves to:

output = loading_setpoint + (r_asset × dt_seconds)

The ramp accumulator therefore has no memory. Output is not the integral of the ramp rate; it is a setpoint plus a fixed per-tick increment. The observed 1 MW/tick rise is correct only because demand happened to rise alongside it. The ramp-rate constraint is not being simulated.

Everything that depends on turbines being ramp-limited is affected: §7.2 arbitration, §7.3's worked example, the BESS bridging window, the insufficient-reserve check, and the aggregate-ramp figures on the Gas Turbine Fleet tile.

The rule to restore: exactly one writer per field per tick.

Whether any state is currently written by both. This is the set to be eliminated.

Stop and report the table before making any change.

Phase 2 — Apply the fix

The partition rule: the loading layer controls only states that advance() does not write.

Change the _synchronised_units construction at simulation_core.py:641-644 so the loading layer operates on the dispatchable-and-not-ramping set derived in Phase 1.
Do not change the is_synchronised property at asset_modules.py:810-814. Contingency evaluation, UnitAvailability, and turbine_output_mw aggregation all consume it, and narrowing it globally would break N−1 and availability reporting. The fix is at the loading layer's call site only.
Do not change advance().
Add a comment at the changed site stating the invariant: one writer per field per tick, and which layer owns which states.

If Phase 1 shows the partition cannot be made clean without a state-machine change, stop and report rather than improvising one.

Phase 3 — Prove the ramp integrates

Add two new tests. These are the proof that the defect is gone; without them the fix is unverified.

Test A — ramp is rate-determined, not setpoint-determined. Single turbine, r_asset_mw_per_s=0.2, dt=5s. Command a ramp toward a target. Assert output rises by exactly 1.0 MW per tick within tolerance, and that the value at tick n equals n × r_asset × dt — i.e. it is the accumulated integral, independent of what the loading setpoint is doing.

Test B — falsification: setpoint drop mid-ramp does not pull output down. Single turbine mid-ramp. Inject a step that drops the loading setpoint well below the turbine's current accumulated output (a solar step is the natural mechanism). Assert the turbine's output continues on its ramp and does not fall to the setpoint. Under the current defect this test fails; under the fix it passes.

Test B is the one that matters — it fails today for the right reason. Confirm it fails before the Phase 2 change and passes after, and report both results.

Name these descriptively. Spec acceptance-test numbering is deferred until §7.1.2 exists — do not assign TC numbers.
