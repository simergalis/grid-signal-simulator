Replit Agent Instruction — Turbine Physics and Operator Service Override

Scope: turbine physics (droop, continuous loading, unit states) plus a live operator take-out-of-service / bring-into-service override, recorded as a replayable scenario.

Deliberately deferred: automatic commitment logic, sub-MSL resolution, N−1 three-state rework. See Deferred at the end. Do not implement them, do not build toward them.

Target model: core/simulation_core.py (live engine) and the turbine asset configuration it reads.

Explicitly out of scope: gridsignal_logger.py. Separate physics implementation, reached only by /api/export/telemetry-log. Do not read, modify, or import from it. If a change appears to require it, stop and report.

Spec basis: Forecast Engine Functional Spec v2.5 — §7.1, §7.1.2, §12, §19 page 4, §27.1, §28.4. Tests TC-58, TC-64, TC-68.

Standing constraints
No new fleet abstraction. Turbines already exist as configured assets with rated output, r_asset, and a target_output_mw() contribution to forecast_mw. Extend that model. A second turbine model produces two contradictory MW figures on one screen — this has happened three times (solar, balance decomposition, aggregate power) and the fix has been deletion every time.
No new transport. Existing FastAPI + WebSocket tick broadcast, existing React drawer. No Flask, no CLI, no matplotlib.
No runtime RNG. random must not appear in any tick path.
No parameter tuning as a fix. Diagnose the mechanism.
No literals in TSX. Every rendered scalar comes from a typed TickPayload field.
GridSignal issues one fleet-level scalar, never per-unit setpoints. A per-unit MW command on a paralleled AC bus is adjacent to a droop command, which TC-68 prohibits. Matched droop governors already distribute load.
No instant transitions. Nothing in this work sets output to zero or to rated in a single tick. Every output change is ramp-limited, in both directions.
